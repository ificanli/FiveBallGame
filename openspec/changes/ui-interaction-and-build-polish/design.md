## Context

M3 的玩家界面是 `technical_table.gd` 里一段 399 行的 `_draw()`，用 `draw_string` / `draw_rect` 手绘 HUD、奖励卡片和结算文字。它能跑，但交互靠快捷键 + 鼠标命中检测，没有可复用的按钮、面板、滚动、悬停状态、菜单或模态层。18 枚徽章只有 `name` 字段，没有中文 `description`；道具只有“Q 用第一个可用”一种入口；流派之间没有视觉身份。

M3.5 的风险不在“能不能画个按钮”，而在：改 UI 的同时破坏 M1/M2/M3 的确定性回放与跨平台 Hash，或者把规则逻辑搬进场景节点造成第二套真相。因此本设计先锁死边界，再谈 UI 结构。

## Goals / Non-Goals

**Goals:**

- 用 Godot Control 节点替换手绘表现层，提供可点击、可键盘、可读的中文界面。
- 补齐主菜单、暂停、奖励、道具、徽章、结算、统计的完整交互闭环。
- 为全部 18 徽章与 6 道具提供中文说明与流派/角色标签。
- 三条打法有肉眼可辨的视觉身份，并通过真人录像判断可辨识性。
- M1/M2/M3 回放、Hash 与自动测试全部保持通过。

**Non-Goals:**

- 不新增徽章、道具、流派、球桌、成长维度或新规则。
- 不实现音效、音乐、手柄、完整设置中心。
- 不实现 Steamworks、联网、PvP、元进度、云存档。
- 不引入正式商业美术；M3.5 使用可发布占位图形与排版。
- 不以 UI 改版代替流派平衡证据，也不以机器人胜率证明流派好玩。

## Decisions

### 1. UI 是表现层，规则真相不变

新增 UI 节点只负责：渲染快照、收集玩家输入、通过既有命令对象调用控制器、显示结果。`RunController` / `CoreLoopController` / 回放 / `RunSnapshot` 保持纯数据与纯逻辑，不引用场景节点。

任何 UI 交互最终必须映射为既有命令（瞄准、出杆、结算、保留、装备/替换徽章、使用道具、重开、开始 Run），不得新增第二条规则路径。验收用规则回放证明：同一命令序列无论走 UI 还是 Headless 都得到相同 Hash。

### 2. 界面分层：场景 + 面板 + 组件，不复用手绘 `_draw`

玩家界面拆为：

- `main_menu.tscn`：开始巡回、教程、退出。
- `run_screen.tscn`：球桌 + HUD + 面板层。
- 面板组件：奖励三选一、道具选择器、徽章管理（替换/排序）、杆后决策、Run 结算统计、暂停。
- 组件用 `Button` / `PanelContainer` / `ScrollContainer` / `Label` / `OptionButton` 等标准节点，主题色、字体、间距统一。

手绘 HUD 只保留球桌、球、墙壁、辅助线、轨迹预览这些必须画在 `Control._draw()` 里的内容；按钮、文字、卡片、菜单全部改为节点。

### 3. 内容文案进本地化表，徽章/道具补 `description` 键

`BadgeCatalog` / `ToolCatalog` 增加稳定的中文 `description_key`（英文内部 ID 不变），`LocalizationZhCn` 补齐 18 徽章 + 6 道具的 `badge.<id>.desc` 与 `tool.<id>.desc`。说明文案写“触发条件 + 效果 + 数值”，不写营销空话。

审计规则扩展：缺失键、空字符串、重复键、过长单行（无换行且超容器宽度）均判失败。

### 4. 流派视觉标识是表现层常量，不进规则数据

三条打法的图标/配色/标签作为 UI 常量表维护，键用 `pure_combo` / `rail_chain` / `wall_risk`。它们只影响显示，不进入结算、Hash 或回放。装备、奖励、结算明细和统计面板复用同一套标识，避免同一流派在不同界面长成不同样子。

### 5. 平衡微调与可辨识性是两条独立证据链

数值平衡由确定性代理做反事实对照（三套 Build 的“直取” vs “流派路线”触发差异），只产出候选调整，不直接改数值。真人可辨识验收要求：隐藏分数 UI，播放三套代表性击球录像，由产品负责人仅凭力度、撞库、连锁、功能墙选择判断流派；自动代理不得代替该结论。

平衡结论仍标 `HUMAN_VALIDATION_REQUIRED`，不宣称“好玩”。

## Risks / Trade-offs

- **改 UI 破坏回放**：命令序列 + Hash 回归门挡住；任何回放漂移即回滚该 UI 提交。
- **节点 UI 与手绘坐标打架**：球桌 `_draw()` 保留，面板用独立层，通过 `z_index` 与模态层隔离，禁止面板与球桌混在同一个 `_draw()`。
- **说明文案过长撑爆布局**：长文案必须支持换行 + 滚动，双分辨率布局测试兜底。
- **流派标识流于装饰**：标识必须与真实触发条件一致，避免“看着像连锁、结算却是纯分”的假身份。
- **范围膨胀**：音效、手柄、完整设置、商业美术明确 CUT，超出即回提案重新审批。

## Open Questions

- 辅助线默认档与音效开关是否需要在 M3.5 内做成持久化设置，还是仅本局生效？默认仅本局生效，持久化留后续。
- 三套流派视觉标识采用文字标签还是图形图标？M3.5 用“配色 + 文字标签”，图形图标后续美术阶段再补。
