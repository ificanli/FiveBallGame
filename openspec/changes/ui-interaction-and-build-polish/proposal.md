## Why

M3 已经把规则、物理、三套流派和中文界面做出来了，但玩家界面仍是 `technical_table.gd` 里一段 399 行的 `_draw()` 手绘：没有真正可点击的按钮与面板，没有主菜单、暂停、道具选择器、徽章替换界面、Run 结算统计，也没有徽章与道具的中文说明文案。玩家必须背快捷键才能操作，流派之间只有数值差异、没有肉眼可辨的身份。

产品负责人明确要求：PvP 不急，插入 M3.5 做品质提升，重点是 UI 交互完备性与流派打磨。M3.5 不新增内容、不扩流派、不碰联网，只把已有的 18 徽章、6 道具、3 桌 Run 变得“看得懂、点得动、分得清”。

## What Changes

- 把玩家表现层从单文件手绘升级为 Godot Control 节点 UI：面板、按钮、卡片、列表、菜单统一为可点击、可键盘操作、可读的界面；物理、规则、回放真相继续留在纯数据模型，UI 只发送命令并渲染快照。
- 补齐缺失交互：主菜单、暂停菜单、奖励三选一卡片（鼠标悬停 + 点击 + 中文说明）、道具选择器（打开后选具体道具与目标）、徽章替换/排序、结算/保留/爆仓操作面板、Run 结算与统计展示。
- 为 18 枚徽章与 6 种道具补全中文名称、说明与流派/角色标签，覆盖最长文案的换行与 1280×720 / 1920×1080 两档布局。
- 给三条打法增加可读的流派视觉标识（图标/配色/标签），让玩家在装备、奖励和结算明细里一眼分清流派。
- 做流派可辨识性验证：隐藏分数 UI 的三套代表性击球录像由真人判断流派，机器人只提供反事实数据，不得代替该结论。平衡数值调整、内容扩展与核心规则微调延后到产品负责人体验后再定。
- 增加最小设置：辅助线默认档、音效开关占位、语言锁定简体中文；不做完整设置中心。
- 把出杆操作改为网页版设计稿的两种可切换方式：**拉杆出手**（按住拖拽定角度与力度，松开击球）与**精细瞄准**（调向 + 选档 + 点击击球），偏好持久保存；两方式共用同一套五档力度、物理与辅助线，不改变规则与回放。

## Capabilities

### New Capabilities
- `ui-interaction-completeness`: 主菜单、暂停、奖励/道具/徽章/结算/统计的可点击中文界面，键盘与鼠标等价，缺失交互被 CI 拒绝。
- `shot-input-modes`: 拉杆出手与精细瞄准两种出杆方式，可切换并持久保存，共用五档力度/物理/辅助线，不进入规则层。
- `build-identity-polish`: 三条打法的视觉标识、中文说明文案与真人可辨识验收。

### Modified Capabilities
- `simplified-chinese-player-ui`: 从手绘 HUD 升级为节点 UI，仍保持本地化键与英文内部 ID 分离。
- `badge-buildcraft`: 为现有 18 枚徽章补中文说明与流派标签，不改动规则效果与结算顺序。
- `consumable-table-tools`: 补道具选择与目标选择的界面，不改动六种道具的规则语义。

## Impact

- 新增 UI 节点与场景，规则真相仍由 `RunSnapshot` / `CoreLoopSnapshot` / 回放承载；场景节点不得成为规则真相。
- UI 只通过既有命令（出杆、结算、保留、装备徽章、使用道具、重开）驱动状态，不得新增第二条规则路径。
- M1/M2/M3 的物理、组合、徽章结算、补球、回放与跨平台 Hash 保持不变；本地化文本变化不得改变回放 Hash。
- M3.5 第一阶段内容量锁定为现有 18 徽章、6 道具、3 桌，不新增徽章、道具、流派、球桌或数值成长维度；新内容与核心规则微调在体验迭代阶段另行立项。
- 不实现音效音乐、手柄、Steamworks、联网、PvP、元进度、云存档、完整设置中心或正式商业美术。
