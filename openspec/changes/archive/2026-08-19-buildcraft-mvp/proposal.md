## Why

M2 已证明单桌的碰撞收集、组合、结算/保留和爆仓闭环稳定，但它仍没有“为什么下一杆要换一种球路”的长期动机，也没有跨桌选择、补球、残局整理或 Run 起承转合。M3 要验证构筑是否真正改变玩家的力度、撞库、连锁和功能墙路线，而不是只在相同打法后面乘一个更大的数字。

用户同时明确要求下个版本改成中文。M3 因此把默认玩家可见界面的简体中文作为硬性产品要求，不继续累积英文原型债务。

## What Changes

- 引入 18 枚版本化桌边徽章，最多装备 5 枚并按从左到右结算；徽章可读取最佳组合与真实物理事件。
- 将 18 枚徽章收束为三条肉眼可区分的首版打法：纯净组合、撞库连锁、功能墙冒险；每条均有启动器、核心件、放大器、风险/收尾件和跨流派桥梁。
- 采用可解释公式：`(参与数字总和 + 基础分追加) × (组合倍率 + 追加倍率) × 乘算倍率`，逐枚输出结算明细。
- 引入 6 种限量道具：软袋、保险球槽、调色粉笔、数字贴纸、退球钩、清台重开；它们修正局面但不替代出杆。
- 在结算或爆仓后按桌级目标进行确定性补球，避免与现有球重叠并保留基础组合机会。
- 建立 3 张递进球桌和 15～25 分钟短 Run：资格桌、高额桌、庄家桌；开局徽章三选一，前两桌过关后继续三选一，最终形成至少三徽章 Build。
- 提供 Run 胜负结算、简单统计和一键导出本地 JSON，以支持后续平衡测试。
- 将玩家可见 HUD、按钮、操作提示、状态、牌型、徽章、道具、奖励、桌名、胜负与统计默认改为简体中文；内部稳定 ID、存档键、回放字段和测试符号保持英文。
- 增加配置审计、徽章/道具规则测试、跨桌确定性回放、种子化 Build 代理与真人 Build 可辨识验收。

## Capabilities

### New Capabilities
- `badge-buildcraft`: 18 枚徽章、五槽顺序、事件读取、三类数值效果、成长状态和三条打法。
- `consumable-table-tools`: 六种道具的携带、合法时机、目标选择、消耗与原子规则效果。
- `controlled-replenishment`: 结算/爆仓后的确定性补球、合法落点、组合机会和密度保护。
- `three-table-run`: 三桌流程、奖励三选一、跨桌 Build、桌级胜负与 Run 终态。
- `run-statistics-and-balance-evidence`: Run 统计、JSON 导出、确定性代理对照和真人证据边界。
- `simplified-chinese-player-ui`: 默认简体中文玩家界面、本地化键完整性及内部稳定 ID 分离。

### Modified Capabilities
- `five-ball-hand-evaluation`: 从 M2 基础得分扩展为带可追踪徽章步骤的最终结算预览。
- `post-shot-decision-and-bust`: 杆后决策接入道具、补球与软袋/保险球槽的爆仓前置保护。
- `single-table-tutorial-loop`: 由单张教程入口扩展为保留教程并可进入三桌 Run 的中文入口。

## Impact

- 新增纯数据 `RunSnapshot`、徽章实例/定义、道具实例/命令、奖励候选、补球配置和结算步骤；场景节点仍不得成为规则真相。
- M1/M2 物理、五球组合和基础回合状态继续复用；不分叉第二套模拟器。
- 规则随机只从 Run Seed 派生，并记录独立随机流/计数器，避免 UI 帧率或展示顺序改变奖励与补球。
- M3 内容量锁定为 18 枚徽章、6 道具、3 桌；不扩到完整 24 桌、70～90 枚徽章或正式商业美术。
- 不引入 Steamworks、联网、PvP、元进度、云存档、完整设置或手柄支持。
