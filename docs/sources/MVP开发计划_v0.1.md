# 一、MVP 的目的

本 MVP 不是 Steam Demo，也不是比赛网页版的 Godot 复刻。

它只需要回答四个立项问题：

1. Godot 重构后的击球、碰撞和辅助预测，能否达到或超过网页原型的手感；
2. “碰撞收集 → 功能墙加工 → 五球组合 → 结算或保留 → 六球爆仓”的核心，在正式工程中是否仍然清楚、稳定、值得重复游玩；
3. 至少三套构筑能否真实改变玩家的击球目标，而不只是让结算数字变大；
4. 共享球桌 PvP 是否会产生读局、抢球、提前结算和反击欲，而不是纯挫败与等待。

只有四项均取得足够正面证据，项目才进入 Steam 纵切生产。

# 二、核心不变量

开发过程中不得擅自修改：

```text
发射母球
→ 撞到彩色数字球即收入当前球组
→ 被激活数字球实际撞上功能墙后被加工
→ 一杆停止后选择立即结算或保留球组
→ 收到第六颗球时爆仓
```

同时锁定：

- 白色母球无数字、无颜色，不参与组合；
- 数字球实体在被收集后继续留在桌面；
- 本手球、已结算废球和中立球必须有明确状态；
- 功能墙只处理实际撞上它的激活数字球；
- 辅助线与真实运动共用同一套物理实现；
- 核心不改成“落袋后才收集”；
- 台球元素作为物理语言，不承诺传统八球规则；
- MVP 不接入联网、排位和完整 Steamworks。

# 三、MVP 最终交付形态

## 模式 A：单机核心 Run

目标时长：15～25 分钟。

结构：

```text
教程桌
→ 标准桌
→ 功能墙桌
→ 构筑成型桌
→ 结算
```

共 4 张有效球桌，其中教程桌不计入正式 Run 难度。

## 模式 B：本地双人 PvP 黑盒

目标时长：8～15 分钟。

结构：

```text
同一张共享球桌
→ 双方轮流出杆
→ 撞球收集 / 抢取对手暂存球
→ 每杆选择结算或保留
→ 固定杆数后比较累计分
```

PvP 与单机共用物理、组合、球状态和功能墙规则。

## 模式 C：技术与规则测试场

供开发使用，不在公开 MVP 主菜单展示：

- 固定 Seed 球桌；
- 物理重复运行；
- 组合识别；
- 功能墙处理；
- 爆仓；
- 回放；
- PvP 抢球与归属转换。

# 四、MVP 内容范围

## 4.1 球与基础规则

MUST：

- 母球 1 颗；
- 数字球 1～9；
- 4 种基础颜色；
- 每桌同时存在 6～10 颗数字球；
- 未收球 / 本手球 / 废球三态；
- 五球槽；
- 第六球爆仓；
- 一杆结束；
- 立即结算 / 保留球组；
- 受控补球；
- 固定 Seed。

## 4.2 组合

MUST：

- 单球；
- 对子；
- 三条；
- 炸弹：四个相同数字；
- 五球满贯：五个相同数字；
- 三至五球顺子；
- 三至五球同色；
- 三至五球同色顺。

计分只选择一个最佳组合，不叠加多个牌型。

## 4.3 功能墙与桌面机关

MUST：

1. 标准库边；
2. 复制墙；
3. 染色墙。

SHOULD：

4. 指定落袋 / 回收口，只用于清理废球或提供附加奖励；
5. 一种改变反弹行为的章节机关，例如镜面库边。

CUT：

- 传送门；
- 移动墙；
- 数字加减墙；
- 多种复杂充能规则；
- 传统台球报袋与八球分组。

## 4.4 徽章

MVP 只做 18～24 枚高质量徽章，覆盖三套主要流派。

### 流派 1：纯色 / 染色工程

目标行为：主动把指定球送入染色墙，制造同色和同色顺。

建议内容：

- 2 枚启动器；
- 3～4 枚核心件；
- 2 枚放大器；
- 1 枚风险核心。

### 流派 2：重复数字 / 复制 / 炸弹

目标行为：主动控制复制墙触发球，追求三条、炸弹和五球满贯。

建议内容同上。

### 流派 3：撞库 / 连锁碰撞技巧

目标行为：为了多库、间接激活和特定力度，主动选择更复杂的球路。

建议内容同上。

### 徽章质量标准

至少 70% 的徽章必须改变以下一项：

- 优先撞哪颗球；
- 是否主动使用功能墙；
- 使用哪档力度；
- 是否追求撞库或间接碰撞；
- 何时结算；
- 如何处理污染球与废球。

纯 `+分` / `+倍率` 只作为少量节奏校准件。

## 4.5 道具

MUST：6 种。

建议：

- 清台重开；
- 软袋：一次爆仓保护；
- 调色粉笔；
- 数字贴纸；
- 退球钩；
- 功能墙充能。

MVP 不做大规模道具池。

## 4.6 球桌

正式桌共 3 张：

1. **标准桌**：验证核心组合和球感；
2. **染色桌**：染色墙成为主要球路目标；
3. **复制桌**：复制墙与炸弹流成型。

教程桌单独存在。

每张正式桌必须改变球路问题，不能只改目标分和障碍位置。

## 4.7 视觉范围

美术基线：台球 + 风格化。

MVP 必须重新制作：

- 主菜单；
- 球桌 HUD；
- 球组与组合区；
- 徽章奖励界面；
- 结算；
- 设置；
- 教程遮罩；
- 球体、功能墙和桌面材质。

不沿用网页版 UI 作为正式风格。

美术探索阶段制作 3 张 Style Frame：

1. 机械竞技；
2. 奥术仪式；
3. 俱乐部潮流 / 玩具工坊混合。

最终选 1 套进入纵切。MVP 不要求完整角色动画和多庄家立绘。

## 规则层

尽量使用与 Node2D 解耦的纯数据类：

- `BallState`
- `TableState`
- `ShotInput`
- `PhysicsSimulator`
- `CollisionEvent`
- `WallEffectResolver`
- `HandState`
- `ComboEvaluator`
- `ScoreResolver`
- `RunState`
- `PvpMatchState`

## 确定性物理

- 固定时间步长；
- 自定义圆—圆碰撞；
- 自定义圆—线段 / 库边碰撞；
- 统一摩擦、低速停止和碰撞修正；
- 预测和真实运行调用同一 `PhysicsSimulator`；
- 输入、Seed 和初始状态可完整回放；
- 浮点差异测试在 Windows / Linux 上执行。

Godot 负责显示，不让渲染节点状态成为规则真相。

- 五球槽；
- 组合识别与计分；

- 爆仓；

交付：

- 18～24 枚徽章；

通过条件：

- 三套 Build 的击球录像肉眼可分；
- 玩家拿到核心徽章后主动改变球路；
- 一局能稳定成型至少一套 Build；
- 不依赖纯倍率膨胀制造差异。

## M4：PvP 核心黑盒（7～10 天）

交付：

- 本地双人轮流；
- 共享固定桌；
- 双方球组与累计分；
- 暂存球阵营外环；
- 抢球；
- 结算 / 保留；
- 爆仓；
- 每方固定 8 杆；
- 简单 AI；
- 对局统计。

通过条件：

- 玩家会主动抢关键球；
- 玩家会因怕被抢而提前结算；
- 至少存在一次“经营自己组合 vs 拆对手组合”的真实取舍；
- 被抢带来反击欲多于纯挫败；
- 非行动方能持续读局；
- 单局不超过 15 分钟为优先目标；
- 先手胜率在可修正范围内。

PvP 未通过则退出 MVP 正式范围，不影响单机继续立项。

## M5：正式表现与可发布 MVP（10～15 天）

交付：

- 选定一套正式视觉；
- 重做菜单和 HUD；
- 球体与墙体正式材质；
- 核心音效与基础音乐；
- 功能墙动画；
- 徽章触发与结算演出；

- 完成首轮外部试玩。

## 总周期

预计 6～9 周。

其中：

- 2～3 周完成技术与单机核心；
- 2～3 周完成构筑与 PvP 验证；

# 九、MVP 停止与转向条件

## 停止 Godot 全量迁移

若 M1 出现：

- 手感明显弱于网页版本；
- 预测与实际难以统一；
- 确定性成本超过产品收益；
- 新机关开发效率明显低于 Web；

则暂停全量迁移，重新评估 TypeScript 桌面方案。

## 暂停构筑扩展

若 M3 出现：

- 三套 Build 录像看起来相同；
- 玩家仍只打最容易撞到的球；
- 核心徽章只影响分数，不影响球路；

则先重构徽章，不继续加数量。

## 放弃直接 PvP

若 M4 出现：

- 抢球主要产生纯挫败；
- 非行动方明显无聊；
- 玩家总是立即结算；
- 玩家只拆对手，不经营自己组合；
- 对局超过 20 分钟；
- 先手优势难以修正；

则 PvP 不进入 Steam 1.0。保留异步同种子、每日挑战和幽灵竞分。

# 十一、MVP 通过标准

只有同时满足以下条件，才能进入 Steam 纵切与正式商店页阶段：

## 技术

- Godot 手感不低于网页版本；
- 固定输入可复现；
- 预测与真实运动一致；
- Windows 导出稳定；
- 20 局无阻塞 Bug。

## 单机

- 陌生玩家 3 分钟内理解碰撞收集；
- 15～25 分钟 Run 有完整起承转合；
- 至少 3 套打法能被肉眼区分；
- 玩家会因徽章改变球路；
- 第二局开启率与定性反馈支持继续开发。

## PvP

- 若通过：能产生抢球、提前结算、读局和反击；
- 若不通过：明确退出，不拖累单机立项；
- PvP 不作为单机项目通过的必要条件。

## 产品表现

- 正式 UI 不再像网页版比赛壳；
- 30 秒视频无需长解释即可展示核心；
- 球、数字、颜色、归属和功能墙在运动中可读；
- 美术方向支持后续章节扩展。
